# КОД / СПОРТ

Финальная версия платформы ФСП Оренбургской области, 28.10.2026.

## Запуск с Docker

Установите Docker с Compose. Из корня проекта:

```sh
cp .env.example .env
docker compose up --build -d
```

В Windows PowerShell используйте `Copy-Item .env.example .env`.
Платформа: http://localhost:5080 . Письма демонстрации: http://localhost:8025 .
Проверка сервера: http://localhost:5080/health . Данные сохраняются в Docker volume.
Остановка: `docker compose down` (без `-v`, чтобы сохранить данные).
Docker-конфигурация подготовлена; фактическая сборка Docker в рабочей среде не выполнялась.

Без Docker нужны .NET SDK 10 и Python 3.10+ для тестов:

```sh
export ASPNETCORE_ENVIRONMENT=Development
export ASPNETCORE_URLS=http://localhost:5080
export Demo__Enabled=true
export Demo__Password='Demo-Orencode-2026!'
dotnet run --project src/Orencode.Web
```

В PowerShell вместо `export NAME=value` используйте `$env:NAME = 'value'`.
SQLite создаётся автоматически; NuGet-пакеты восстанавливаются при первом запуске.

## Короткий сценарий презентации

1. Федерация создаёт соревнование и открывает приём в его карточке.
2. Спортсмен подаёт заявку. Федерация допускает его в разделе «Заявки».
3. Федерация назначает действующего судью в карточке соревнования.
4. Судья входит отдельным аккаунтом, вносит баллы, публикует протокол.
5. Спортсмен показывает историю и QR-справку. Федерация — рейтинг и экспорт.
6. Дополнительно: тренер запрашивает связь; спортсмен подтверждает её в ЛК.

Для демонстрации допустима публикация результатов будущего тестового события.

## Стек и устройство

ASP.NET Core 10, C#, SQLite / Microsoft.Data.Sqlite 10.0.14, QRCoder 1.6.0.
Фронтенд: HTML, CSS, JavaScript, без сборщика. Оформление основано на предоставленном HTML.
Cookie HttpOnly, серверная проверка роли и связей, CSRF, хеши паролей, аудит.
OpenXML DOCX/XLSX формируется сервером. PDF справки — через печать браузера.

SQLite хранит JSON каждой сущности в отдельной таблице. Команда выполняется транзакционно.
Приложение рассчитано на один экземпляр и небольшую хакатонную базу.
Модель и API описаны в [docs/API.md](docs/API.md).

## Развёртывание с HTTPS

1. Направьте DNS домена на сервер с открытыми портами 80/443.
2. Заполните в `.env` DOMAIN, ADMIN_EMAIL, ADMIN_PASSWORD и параметры SMTP.
3. Запустите `docker compose -f compose.production.yml up --build -d`.
4. Проверьте `/health`, вход администратора и доставку тестового уведомления.

Production создаёт только администратора на новой БД; демо выключено.
Caddy завершает TLS, приложение доверяет forwarded-заголовкам только указанному прокси.
SMTP использует STARTTLS, обычно порт 587. Значения из `.env` не публикуйте.
Сохраняйте весь `/data`: БД, ключи cookie/OIDC и приватные загрузки.
Для резервной копии остановите приложение и скопируйте весь volume, затем запустите снова.
Восстановление выполняйте в остановленный экземпляр с сохранением прав пользователя app.
